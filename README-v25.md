# 五行战记 V25：资源越界与死亡结算修复

直接游玩：https://dragonking888866.github.io/5elements/?v=25.0.0

旧故障页面如果仍开着，先从菜单→系统存档导出当前进度，再在V25导入。这样可以保留尚未成功写入的进度。新版也会从本浏览器V24及旧版保存自动迁移；旧键不会删除。普通档与口令档仍分离。

## 已复现的根因

未修改的V24执行 /resources max 与 /level max 后：药剂100000。普通掉落继续加药，变成100001，违反基础存档规则；后续加点、天赋和熔炼因此被同一校验拦住。Boss首通的两瓶药也使奖励事务失败；死亡回滚保存的是已经扣为负数的生命值，造成负血Boss不死。

另查到：满级灵宠经验持续累积，以及口令分配骑宠时在外层事务提交前提前保存，均已修正。

## 修改

- 所有恢复药剂奖励统一走数量上限，超出每瓶折5金币；钱包满则进入金币储备。金币奖励不再直接越界。
- 普通怪与Boss奖励都原子结算。经验、掉落、材料、死亡和主线战绩一次保存，失败恢复正生命和原护盾，不发放假奖励。死亡生命值固定0。
- 满级灵宠经验不无限累积。已知有限资源越界会先备份、回读，再修复；未知坏字段继续拒绝。
- 基础校验和错误定位使用同一套规则，显示如 potions=100001（0至100000）或具体装备路径。
- 内层保存请求延后到外层事务的最终校验提交，避免半成品存档。
- 继续游戏、文件导入及原生导入都支持已知溢出的安全修复，原文件、装备、灵宠和宝石保留。

主要文件：integrity-v25.js、game.js、upgrade.js、session-v23.js、recovery-v22.js、growth-v10.js、divine-v17.js、各旧奖励入口、版本存储与构建文件、tests/combat-v25.cjs。

## 验证

351项全部通过（329项原回归＋22项新测试），含500次真实伤害/掉落链、20轮间歇加点和40次熔炼、十张地图Boss、满级宠经验、重复结算防护、存储拒写回滚、旧故障存档导入和嵌套保存。

浏览器实测：使用V24代码产生药剂100001的故障导出文件，V25导入后正常击败Boss、救出1级英雄，手机横屏连续加点、天赋、再次使用口令、两次熔炼失败及两次熔炼成功，横竖屏结果无横向溢出。没有物理手机认证。

运行：`node tests/release-v25.cjs`；构建：`node build.cjs`。详细证据见 QA-v25.json。
