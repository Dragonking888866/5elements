# 五行战记 V19 · 循序远征

直接游玩：https://dragonking888866.github.io/5elements/?v=19.0.0

这是现有游戏的代码升级，沿用 2.5D 画面、五行战斗、装备、灵宠、宝石、转职、单人游戏口令及独立沙盒。V19 主要修复关卡权限和传送，并升级属性、返回操作、支援控制与宝石商店。

## 从哪里使用新功能

- 左上角金币和灵铁：点击打开完整资源账簿。手机端只常驻两个简短数字。
- 点击英雄信息 → 属性：顶部是当前实际 STR / INT / AGI；点击属性卡展开来源。面板中可直接切换英雄。
- 菜单 → 逐关旅图：查看全部主线的首领、推荐等级、奖励、状态和入口。手机也可从“传送”进入。
- 菜单 → 宝石货架，或营地宝石商店：点击商品图查看详情，选择数量后购买。横屏手机的筛选区默认收起，点击“五行 / 品质 / 名称”展开。
- 菜单 → 英雄 / 支援编队：选择全部英雄、全部支援或混合编队。手机战斗区“更多”中也有支援和混编入口。
- 功能窗口按 Esc 或手机右上角 X 返回一层。支持 History API 的浏览器，其返回键也按相同层级处理。

## 关卡错误的实际根因

检查发现，旧主线地图的普通出口共用了地图 6（永恒裂隙），没有逐一配置下一主线关卡；旧版又允许达到等级条件提前进入裂隙，解封五位英雄即可进入归墟。因此实际进入权限和剧情通关状态存在多条互相独立的判定。

没有发现所有出口被字面写死为地图 5 的代码。V19 修复的是实际复现出的出口目标共用、权限条件过宽和存档状态污染，避免仅改名称而留下底层问题。

另一个已经复现的存档问题：旧裂隙与界外战斗会临时把 `chapter` 提升为 4、抬高清怪计数，以放行战斗；持续伤害击杀过程中触发保存时，可能将临时状态写入磁盘。恢复内存变量后，磁盘中的章节与首领记录仍然矛盾，造成读档校验失败。V19 删除这些临时修改，独立用 `enemyEligible19` 判断战斗资格。

## 完整关卡关系

所有主线关卡使用稳定的地图 ID。营地和资源谷独立开放；隐藏图另有条件。

| ID | 地图 | 进入前提 | 通关后的普通出口 |
|---|---|---|---|
| 0 | 青禾营地 | 初始开放 | 只能使用已解锁关卡的入口 |
| 1 | 翠影迷林 | 初始开放 | 2：熔火裂谷 |
| 2 | 熔火裂谷 | 通关 1 | 3：霜镜群岛 |
| 3 | 霜镜群岛 | 依次通关 1—2 | 4：沉岳古城 |
| 4 | 沉岳古城 | 依次通关 1—3 | 5：无相王庭 |
| 5 | 无相王庭 | 依次通关 1—4 | 6：星渊·永恒裂隙 |
| 6 | 星渊·永恒裂隙 | 依次通关 1—5 | 7：归墟浮陆 |
| 7 | 归墟浮陆 | 依次通关 1—6，五位英雄全部解封 | 8：九幽炼狱 |
| 8 | 九幽炼狱 | 依次通关 1—7，五位英雄全部解封 | 9：太初神庭 |
| 9 | 太初神庭 | 依次通关 1—8，五位英雄全部解封 | 主线完成；另检查隐藏入口 |
| 10 | 时隙秘境 | 依次通关 1—9并获得归墟、九幽、太初三枚印记 | 独立隐藏支线 |
| 11 | 丰饶资源谷 | 初始开放 | 返回营地；不推进主线 |

第 1—5 关须完成本关清怪条件，解除首领屏障后击杀首领。后续主线以击杀本关实际首领完成通关。结算奖励并保存后，在救援/通关剧情中追加“进入下一关”按钮，同时激活本关正确出口；玩家可以留下，不会在救援或掉落结算中被强制送走。返回营地沿用回城卷轴规则。

所有地图菜单、NPC 入口、传送门和底层 `enterMap` 都使用同一权限判定。即使去掉按钮的 disabled 状态或传入 force 参数，也不能跳过前置。这里是本地单人游戏的程序校验；没有新增可信联机服务端，不能宣称能阻止玩家直接修改本机脚本或存档。

### 多角色与首领状态

存活且在当前地图的英雄随队进入新图；死亡并留在营地的英雄不会被错误搬入新图。一名英雄倒下不会重置仍在交战的首领。所有有效英雄离开未通关地图后，首领按出生基准恢复生命、攻击和阶段，避免阶段缩放反复累乘；已通关标记、首领击杀次数与既有封印记录保留。

### 旧存档迁移

正常存档使用 `wuxing-chronicles-v19`，可回退读取 V18、V17 和更早的兼容存档。V19 增加 `systems19` 与 `progression19.cleared`，依据主线首领标记、对应首领的实际击杀记录、裂隙救援记录和后界通关记录建立通关账本。

- 角色等级、当前所在地图、章节数字、已拥有五位英雄均不能单独证明通关。
- 被临时章节值污染的旧档会按真实战绩修复章节；修复不会发放第二次金币或物品。
- 已有英雄、装备、灵宠、宝石、奖励和高级地图的真实通关记录保留。
- 后界有真实战绩但前置缺失时，保留后界记录，要求依序补齐缺口后才开放后续入口；不会把未打过的关卡算为通关。
- 存档当前地点已经不符合权限时，将玩家安全放回营地并显示校验说明。
- 非法物品、畸形数据、重复或越界的关卡 ID 仍会拒绝。

## 三大核心属性如何计算

总值直接读取原战斗系统唯一的 `stats(heroIndex)` 返回值，面板不另建一套战斗数值，也不会在打开面板时给角色加点。

来源明细拆为：英雄初始基础、当前等级成长、已投入自由属性、永久成长银行与旧天赋、装备本体、宝石与神石、当前有效灵宠，以及专精/状态/取整差值。最后一项与前面来源相加，严格等于战斗总值。

当前规则中：靴子本体提供对应敏捷；武器宝石按 100%、其他装备宝石按 50%、灵台宝石按 65% 生效；五行神石的核心属性 +80 按英雄去重；灵宠使用实际有效契约的 `petPower10`。细节以战斗规则常量为准。部分灵宠提供小数加成而最终属性取整，因此来源中可能出现如 -0.4 的取整差值。

“永久”一栏包含基础、等级成长、已分配属性与永久成长/旧天赋，排除装备、宝石和可更换灵宠。现有药剂有些改变攻击、防御等派生能力，本身不改变 STR/INT/AGI；面板不会为这些药剂虚构核心属性加成。更换角色、装备、宝石或有效灵宠后重新渲染当前面板，购买等事务返回上层时也会刷新受影响的内容。

保留 +1、+5、+10、+100、MAX、职业推荐、预分配预览和确认保存。

## 窗口管理与返回

`windows-v19.js` 统一接管 `showDialog` 和 `closeDialog`。只挂载一个大面板，上层内容打开时将父层节点和事件暂存，最多保留 12 层；同一面板刷新或切换英雄不会无限堆叠。

全项目只保留一处 Esc 监听，使用捕获阶段处理，所以输入框有焦点时也能返回。Esc 关闭顶层、取消未确认的操作；无窗口时打开暂停。长按按键的 repeat 不会连续穿透多层。关闭时停止长按购买、暂停批量材料操作、清理摇杆与按键状态。

返回父层恢复节点、选择状态、滚动位置和焦点。若期间发生了交易，会重新渲染有上下文的父面板，避免显示旧金币/库存。手机 X 使用同一个函数；浏览器返回采用每次窗口会话一个历史标记，逐层退出，根窗口退出时释放标记。

## 支援单位

六类支援分别使用星术学徒、行医者、持盾护卫、巡林弓手、游剑侍从、驭兽祭司外观。独立绘制服装、头部、手持物和走路/攻击/施法动作，没有调用或缩小英雄的完整模型。视觉高度约 102—110，相对参考英雄 150 约为 68%—73%；脚底碰撞半径和实际攻击距离独立计算。

沿用五位主英雄、两席上阵支援和候补名册。支援使用独立 actor、选择 ID、生命与军令，不占用英雄名额，不参与英雄转职和觉醒。可选全部英雄、全部支援或混合编队；点地、支援模式下的 WASD/手机摇杆、进攻、驻守、跟随、进攻移动、撤退按当前分类执行。界面标记“支援”或“混编”，避免把支援计为英雄。

治疗、护盾、回蓝、伤害分担、驭兽治疗和缩短灵宠冷却继续真实生效。英雄原有 Ctrl+数字编队仍为英雄编队，新增支援分类作为当前控制范围，不将支援 ID 塞入五位英雄的旧编队数组。

## 宝石货架

取消商品下拉选择，以卡片显示图片、名称、等级、品质、五行、单价、库存和已有数量。前 18 类基础宝石按等级与普通/精品品质形成商品，8 项一页；高级条件满足后加入 Lv.3。支持五行/品质/名称筛选、等级或价格升序、分页、单件/批量/自定义数量。

24 类宝石采用不同切面与五行图形的 SVG 图像；高阶宝石有发光效果，五行神石沿用专用图像。数量下拉仍是购买数量控件，商品本身已经完全由货架选择。

点击图片打开独立详情：显示效果、持有量、金币/储备、库存、本次成本、购买后数量，以及换入当前英雄武器第 1 孔的前后属性预览。预览不会免费镶嵌或改变装备。实际镶嵌仍进入原可视化镶嵌台。

购买复用原事务系统，逐次检查营地/入口安全区、整数数量、容量、库存、余额与进度。普通商品每日上限 50 枚，三级 20 枚；失败不扣款，并给出原因。Lv.3 必须真实依次通关第 1—4 关、开放第 5 关且五位英雄解封；仅站在第五关、提高等级或修改章节不会开放货架。

## 验证与已知范围

自动化覆盖原有系统及新增属性、单层/多层返回、交易与资源回滚、九关实际逐一通关、旧档迁移、死亡留营、首领重置、独立支援、锁定门、点击寻路宝箱和宝石货架。关卡通关功能测试使用隔离测试档和极高伤害来验证流程，不是正常装备难度评测。完整通过数与 600 秒战斗模拟数据记录在 `QA-v19.json`，发布文件哈希结果记录在 `PUBLIC-VERIFICATION-v19.json`。

浏览器使用隔离的本地测试档，检查电脑版、手机横屏、竖屏、小尺寸横屏、方向切换、购买、输入框 Esc、浏览器返回、角色面板加点及切换、支援点地移动和宝箱自动接近。没有覆盖在线玩家存档。

当前仍是 2.5D 本地单人网页游戏；未新增联机服务器或账号云存档。本次没有进行实体安卓手机、iPhone 或原生 Safari 手势测试，浏览器视口检查不能代替真机验证。完整 3D 模型、原生应用商店签名/上架不属于本次专项交付。支援新外观为代码绘制动画，清楚区分身份，尚未替换成与英雄相同精度的贴图资产。

本地运行：`node build.cjs` 构建，再使用任意静态服务器启动 `web/`。自动化检查：`node tests/release-v19.cjs`；持续模拟：`node tests/stability-v19.cjs`。发布仓库使用网页文件平铺结构，其构建路径和测试路径已随交付调整。
