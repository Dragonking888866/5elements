# 五行战记 V29：融合结算、统一养成经济与装备外观交付说明

直接开始：https://dragonking888866.github.io/5elements/?v=29.0.0

## 1. 灵宠融合没有扣费的实际原因

旧单机口令和沙盒的无限资源层以 virtualWallet16/15 替换钱包，再在 finally 中恢复；spendGold10 与 pay17 也会在该模式跳过真实扣除。旧普通灵宠融合本身仅收金币，没有灵铁和五行精华。这两条路径分别造成“免扣费”和“未实现相应费用”。

现在三类养成使用严格结算作用域，统一调用 calculateCosts29、validateCosts29、consumeResources29、commitOperation29。该作用域内不走虚拟钱包，口令无限资源和沙盒无限资源都不能免掉此次融合/淬炼的费用。无敌、冷却、100%融合等原有体验开关仍独立工作；/resources max、/materials max 同时补充新材料，随后按实际余额扣费。正式档与独立口令档仍隔离。

## 2. 宝石熔炼没有扣费的实际原因

resourceFree17 为真时，旧熔炼代码把原料变化写成0，又把产物写成+1；pay17 同时直接返回成功。因此投入宝石保留，产物却增加，金币与灵铁也不减少。新逻辑明确构造 -3+1 或失败 -2 的原料变化，真实扣除三类费用，保留宝石资产唯一ID规则。

## 3. 灵宠库异常增长的实际原因与排查边界

旧 pet-fusion 事务会在成功后把快照中“消失”的灵宠重新加入包裹。异变模式又为结果生成新ID：两只旧宠被补回，再加一只新宠，就会出现2→3；同种升品也可能把已消耗的副宠补回。V29直接在主宠原记录上进化，异变也保留主宠ID；仅移除副宠，净减少1只，主宠培养与骑乘归属保留。

未发现宝石数组与灵宠数组共用引用，旧宝石单独熔炼直接增加灵宠的路径也未在本次复现。不能据此编造跨背包引用错误。新结算会比较熔炼前后完整灵宠内容、ID和数量，任何变化都会拒绝并整体回滚；已在普通档、无限资源口令档、隔离沙盒与连续批量中验证不变。

不依据猜测批量删除旧宠，也不追扣历史资源。既有合法身份、旧融合记录和历史物品继续保留；新规则从本次以后执行。

## 4. 原子结算、隔离与防重

每次确认携带唯一操作ID、预览修订号和当前世界信息；复用同一确认不能再次结算。仍使用原有WebLock、页面存档所有权、原子保存和回读核验，不增加第二套资产数据库。

提交前检查对象、同品质、保护状态、原料数量、材料、金币与灵铁；验证通过后只进行一轮随机，构造完整结果，再提交保存。正常随机失败是已完成交易，资源照扣；条件变化、随机源无效、库存守恒不符、存储拒写则回滚资产和资源。

每次提交验证：宠物融合灵宠-1、宝石0、装备0；普通三石宝石-2、宠物0、装备0；神炉成功宝石-4、失败宝石0；装备淬炼三个库存数量均不变。对钱包三类扣除以及非目标库存还做内容检查。最近40笔持久化养成凭证可在“菜单 → 五行材料 / 养成账簿”查看，包括实际费用与前后数量。最近160笔确认令牌及修订号防止重复提交。

## 5. 灵宠融合规则

同品质两只合法宠物，一级即可融合，最高品质不能普通升品；消耗金币、灵铁和主宠所属五行精华。不同五行仍保留相生相克、灵时、共享幸运、失败保护及合法神石保底。成功主宠升一品质，保留ID、最高培养等级、潜能和技能继承；副宠移除。随机失败主宠不变，副宠与三类资源消耗。副宠原骑乘英雄解除关联，其他宠物与宝石不变。

## 6. 宝石规则

唯一核心分级仍为普通、精品、稀有、史诗、传说、神话、极其稀有。三石普通升品投入三枚同种同品质，成功获得一枚下一品质；失败第一槽保留、两副石消耗。公开异种配方保留，以实际产物的主五行为唯一精华类型。锁定、收藏、绑定、已镶嵌资产不会被当作可用原料。

五行神炉仍用五枚极其稀有单元素宝石、五行各一；额外经济资源统一为金币、灵铁、五行源尘。基础费用1000万金币、30万灵铁、100源尘；连续尝试按旧框架递增，冷却15秒，成功5→1，失败保留五枚。原共享幸运与神石相关融合成功率最低70%的条件保留；神石不提升自身炼制，也不提升装备淬炼概率。

## 7. 装备品质提升规则

普通升品仅金币、灵铁及装备本系精华。无显式五行的旧装备使用既有基础部位五行映射；无法映射时用明确金系兜底，避免无属性装备卡死。成功品质+1、威力成长，原ID、孔位、宝石与合法词条保留；失败只扣资源，不毁装、不降品。词条合并保留原有合法能力。

四象套装定向打造也简化为传说基础费用×1.2，即30万金币、1.2万灵铁、360本系精华；仍保留地图解锁、真实冶金铺NPC与容量限制。历史碎片、魂、核心、淬炼石不删除，但不再作为普通品质提升或此次套装定向打造的强制附加费用。强化、附魔、转职等其他玩法沿用其原有规则。

## 9. 装备外观的具体改进

保留Canvas 2.5D引擎，新增共用分层角色绘制函数 drawWarrior29。躯干、披风、肩甲、头盔、臂甲、手、武器、守御、腿甲、靴子使用相同动作空间与层级挂点；武器在手部末端变换，头盔跟随头部，骑乘沿用坐骑鞍位与俯仰变换，并缩放骑乘身体。原有角色面部美术作为裁切纹理保留，装备主体使用原创程序形状、渐变材质、倒角、刻纹和宝石嵌饰。

武器按实际物品身份稳定区分剑刃、弯刀、法杖、弓与战锤形状；同一物品换英雄不会随机换形。品质影响轮廓、边饰、嵌饰、元素纹理与光效；已镶嵌宝石的颜色和品质参与武器表现。戒饰用小型吊坠与灵光，不堆叠大图遮脸。待机、跑动、攻击、施法、受击、死亡、骑乘与转向均使用同一角色函数。

角色装备页增加真实穿戴预览，换装比较页同时展示当前与候选外观；预览通过临时只读装备替换与 finally 恢复，不写资产。提供动作、转向、套装光效开关和低/中/高特效设置，仍保留武器与护甲基本形状；低画质减少持续粒子。修正预览Canvas适配，避免画布比例拉伸角色。

## 10. 四大套装的实现

各部件独立读取真实装备；组合演出要求对应套装六件，卸下任意一件立即解除，死亡不保留活体套装粒子。效果每次绘制重新从装备计算，不把临时光环永久写回英雄。原有2/4/6件战斗收益由原计算系统负责，外观不额外叠加战斗属性。

## 13. 边界与后续平衡

本次是可运行的2.5D分层装备与挂点动画，不是完整3D骨骼模型，也不宣称达到Dota/魔兽商业美术品质。尚未进行实体Android/iOS手机兼容和长时间整场帧率测量。手机结果来自浏览器视口模拟。

最高品质的金币、灵铁、等级修正和低成功率还需要长期玩家反馈；上述经济投影未计入组队效率、死亡、掉落出售和Boss路线，不能当作承诺的通关时长。七品质、五行、镶嵌、骑乘、共享幸运、五行神石和五次转职均保留。没有新增多人服务器或原生安装包。
